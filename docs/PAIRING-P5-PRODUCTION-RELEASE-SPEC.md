# HRack 配对平台 P5：正式生产发布与运营关门规格

> 上游规格：[配对 URL 平台规格](./PAIRING-PLATFORM-SPEC.md)
> 前置：[P4 可复现部署与运维](./PAIRING-P4-DEPLOYMENT-SPEC.md)
> 状态：生产已切流，技术门禁通过；等待实体手机、邮件收件箱、异地备份与发布责任人签署（2026-08-23）

## 1. 目标

P5 不再扩展配对协议，而是把 P1–P4 已完成的账号、持久配对记录、运行时房间恢复和
手机控制能力关门为可正式发布、可持续运营的生产系统：

1. 在真实域名部署并使用受信任 TLS，HTTP 自动跳转 HTTPS，WebSocket 使用 WSS；
2. 官方 `modplex.app` 部署接入已验证域名的 Resend，并强制邮箱验证；
3. 真实完成注册、邮箱验证码、登录和首位管理员初始化；
4. 真实完成手机 ↔ HRack 桌面端的公网配对与终端控制；
5. 产生数据库备份，并在隔离目标执行恢复演练；
6. 增加 Web、Relay、配对协调器健康信号、协调失败告警和容器日志轮转；
7. 用自动检查与人工证据共同完成正式发布清单。

P5 的完成标准是“真实生产链路有证据”，不是单元测试、模拟邮件或只检查配置文件。

## 2. 范围边界

### 2.1 官方部署与自部署

- 仓库继续支持自部署，邮箱验证默认关闭，邮件提供商由部署者选择；
- `hrack.dev` 官方部署必须设置 `EMAIL_VERIFICATION_REQUIRED=1`、
  `MAIL_PROVIDER=resend`，发件地址必须属于 Resend 已验证的 `modplex.app` 域；
- 官方部署策略只写入部署环境，不把官方域名、收件邮箱或 Resend 密钥写死到代码；
- 无邮件的自部署仍可通过一次性 setup token 或固定版本 `web-tools` 初始化管理员。

### 2.2 非目标

- Relay 多副本、多地域容灾或无中断房间迁移；
- Kubernetes、云厂商专有监控或证书签发实现；
- `PAIRING_ENC_KEY` 在线轮换；
- 新增配对协议、重写手机端/桌面端传输层；
- 把运行时房间当成持久事实进行备份。

## 3. 生产不变量

| 编号 | 不变量 |
|---|---|
| P5-I1 | `PUBLIC_ORIGIN`、`BETTER_AUTH_URL` 与浏览器最终 origin 完全一致，官方部署为 `https://hrack.dev` |
| P5-I2 | 证书链受信任、域名匹配且未过期；80 只跳转 443；配对 WebSocket 走 WSS |
| P5-I3 | 匿名创建运行时房间保持 401，system API 与 demo 公网保持 404 |
| P5-I4 | 官方部署的密码注册在真实邮件验证前不能进入 dashboard；OAuth 不能绕过同一策略 |
| P5-I5 | Resend API key、验证码、邮箱、Cookie、配对 URL、roomId 与所有 token 不进入日志或发布证据 |
| P5-I6 | 首位管理员初始化只有一次；成功后删除 `ADMIN_SETUP_TOKEN`，且系统始终至少有一位有效管理员 |
| P5-I7 | 备份包含完整 `web-data` 快照、校验和、代码/镜像版本和密钥版本说明；恢复演练不得覆盖生产卷 |
| P5-I8 | 恢复后用户账号、管理员角色和原配对 URL 不变；协调器只做恢复，不做轮换 |
| P5-I9 | Web、Relay 与协调器均有机器可判定的健康状态；连续协调失败会发出告警，恢复会发恢复通知 |
| P5-I10 | 所有长期容器都设置有界日志轮转；告警与日志仍遵守零敏感信息纪律 |

## 4. 运维模块与接口

P5 在业务代码外建立一个深的“生产运维”模块，调用者只需要以下三个接口：

| 接口 | 行为 |
|---|---|
| `platform-backup create` | 短暂停止写入者、归档 `web-data`、生成 SHA-256 和无秘密清单，最终恢复服务 |
| `platform-backup rehearse` | 只恢复到带演练标签的临时卷，执行 SQLite 完整性检查，随后清理临时卷 |
| `production-monitor` | 周期检查公网 TLS/HTTP、内部 Web/Relay 和协调器心跳；达到阈值后告警，恢复后通知 |

配对协调器只新增一个小接口：每轮写入不含配对身份的健康心跳。心跳包含最近成功时间、
连续失败次数和错误类别；Docker healthcheck 与监控进程读取同一份心跳。业务实现不直接依赖
告警厂商。

## 5. 实施切片

### P5.1 真实域名与 TLS

- DNS 指向生产主机；
- 受信任证书覆盖 `hrack.dev`；
- HTTPS 首页、Relay health、WebSocket Upgrade 均通过；
- HTTP 跳转不降级、不暴露 system API；
- 记录证书颁发者、有效期和部署 commit，不记录任何密钥。

### P5.2 Resend、真实认证与管理员

- 使用已验证 `modplex.app` 发件域；
- 先发送后台测试邮件并确认真实收件；
- 再开启邮箱验证，完成全新邮箱注册、验证码、登录；
- 使用正常注册后的 bootstrap 或一次性 setup 初始化首位管理员；
- 删除 setup token、重建 Web，并验证 `/admin/setup` 不再可用；
- 验证管理员登录、用户管理与审计记录。

### P5.3 公网端到端远控

- 已登录用户创建一条配对记录并取得配对 URL；
- HRack 桌面端连接该 URL；
- 手机 App 从不同网络扫码/打开同一 URL；
- 手机看到真实桌面 PTY 输出，并发送至少一条可识别输入和一个控制键；
- 仅重启 Relay，15 秒内用同一配对 URL 重新连接成功；
- 证据只记录结果与时延，不保存终端内容、roomId 或完整 URL。

### P5.4 备份与恢复演练

- 对生产 `web-data` 生成带 SHA-256 的备份；
- 单独保管 `.env` 长期密钥、TLS 配置和部署版本，不把秘密写入普通日志；
- 使用工具恢复到全新、带演练标签的隔离卷，运行 `PRAGMA integrity_check`；
- 在隔离部署中验证既有账号、管理员角色和原配对 URL；
- 清理隔离容器与卷，不对生产执行 `down -v` 或清空操作。

### P5.5 健康、告警与日志

- 协调器心跳超过阈值未成功则容器 unhealthy；
- 监控同时区分公网、Web、Relay、协调器故障；
- 连续失败达到阈值才告警，状态恢复只发一次恢复通知；
- 官方部署至少配置一个独立告警接收端；
- 注入停止协调器、停止 Relay 两类故障，确认告警和恢复通知真实送达；
- Docker 日志使用 `json-file` 的 `max-size`/`max-file` 上限。

### P5.6 发布关门

- 自动生产探测全绿；
- `typecheck`、单元/黑盒测试、构建和 P4 隔离部署门禁全绿；
- P5.1–P5.5 的真实证据均已登记；
- 发布、回滚、备份和告警联系人明确；
- 文档中的待办、实际配置与部署 commit 一致。

## 6. 自动检查

`npm run verify:p5-release -- --origin https://hrack.dev` 必须以真实网络检查：

- TLS 信任、域名与剩余有效期；
- HTTP→HTTPS；
- 首页与 `/remote/healthz`；
- 匿名创建 401；
- system API、demo 404；
- 基础安全响应头；
- 可选协调器心跳与告警配置完整性。

自动检查不得创建用户、配对记录或管理员，也不能替代真实邮箱与公网 App 验收。

## 7. 发布证据格式

真实验证记录写入部署者的受控运维记录，只允许包含：

- UTC 时间、部署 commit/镜像 digest；
- 域名与证书有效期；
- 每个检查的 `passed/failed` 与耗时；
- 备份文件名、大小和 SHA-256；
- 告警/恢复是否送达；
- 手机 ↔ 桌面公网控制是否成功及重连时延。

禁止记录邮箱全文、验证码、密码、Cookie、Authorization、Resend key、配对 URL、roomId、
revoke token 或终端 payload。

## 8. P5 完成判定

只有以下条件全部满足，平台规格状态才可改为“P1–P5 已完成”：

1. 仓库中的 P5 运维制品与自动门禁已实现并提交；
2. `hrack.dev` 的真实 TLS 与公网边界通过；
3. Resend 真实送达、邮箱验证、登录、首位管理员均通过；
4. 手机 ↔ HRack 桌面端真实公网远控与同 URL 恢复通过；
5. 生产数据备份及隔离恢复演练通过；
6. 故障注入后告警与恢复通知真实送达；
7. 发布清单签署，回滚入口与备份位置已确认。
